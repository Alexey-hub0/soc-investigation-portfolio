# TRIAGE-01 — Mass File Modification

## Общие сведения

Учебное расследование по публичному синтетическому датасету; эталонный ответ на этапе разбора не использовался. Данные не относятся ни к корпоративным журналам, ни к Wazuh-лаборатории из `labs/`. [Источник и ограничения раздела](../README.md).

| Поле | Значение |
| --- | --- |
| ID кейса | TRIAGE-01 / INC-020 |
| Категория | Массовое изменение файлов; проверка версии о шифровальщике |
| Узел | `FILE-SRV-03` |
| Источники | SIEM, File Audit, EDR, Change Management |
| MITRE ATT&CK | Подтверждённая техника не назначена; T1486 рассмотрена как гипотеза |
| Вердикт | Закрытие оповещения отложено до дополнительного подтверждения |
| Критичность | Не зафиксирована в материалах разбора |

## Исходное оповещение

Первое событие записи [INC-020](evidence/original-events.jsonl):

```text
2026-07-01T23:02:00Z siem rule=Mass_File_Modification host=FILE-SRV-03 process=backupagent.exe files_modified=1204 interval_seconds=60
```

На `FILE-SRV-03` процесс `backupagent.exe` изменил 1204 файла за 60 секунд. Такой объём записи возможен и при работе программы-вымогателя, и при резервном копировании, поэтому само оповещение ни одну из версий не подтверждает.

## Результаты анализа

Анализ событий SIEM, File Audit, EDR и Change Management показал, что массовое изменение файлов согласуется с выполнением резервного копирования.

File Audit зарегистрировал создание зашифрованного файла `.bkp` в репозитории резервных копий. EDR подтвердил действительную цифровую подпись `backupagent.exe`, а Change Management — наличие запланированного задания `BK-DAILY-03`, выполнявшегося в тот же период.

Прямых свидетельств шифрования рабочих файлов не обнаружено. Однако связь процесса с заданием резервного копирования не подтверждена: отсутствуют дерево процессов и сведения о завершении задания.

**Результат:** версия легитимного резервного копирования наиболее обоснована, но для окончательного закрытия оповещения необходимы дополнительные данные.

## Анализ исходных событий

| Время и источник | Подтверждённый факт | Значение для вывода |
| --- | --- | --- |
| 23:02:00Z, SIEM | `backupagent.exe`, 1204 изменения за 60 секунд | Объём активности; не доказательство шифрования данных |
| 23:02:04Z, File Audit | Создан `//backup/repository/finance-2026-07-01.bkp`, `encryption=enabled` | Зашифрован резервный контейнер, а не рабочие файлы |
| 23:02:07Z, EDR | Подпись `Approved_Backup_Systems` действительна, `verdict=clean` | Довод в пользу легитимного процесса; хеша, пути и PID нет |
| 23:02:12Z, Change Management | Задание `BK-DAILY-03` владельца `IT-Operations`, расписание 23:00, `status=running` | Поддерживает версию резервного копирования; привязка к процессу и завершение не показаны |

## Сопоставление с MITRE ATT&CK

[T1486 — Data Encrypted for Impact](https://attack.mitre.org/techniques/T1486/) рассмотрена как гипотеза из-за объёма записи и шифрования. Нарушение доступности данных и злонамеренность в этом наборе не подтверждены, поэтому техника не назначена.

## Вердикт

**Вердикт:** закрытие оповещения отложено до дополнительного подтверждения.

**Критичность:** не зафиксирована в материалах разбора.

**Уверенность:** имеющиеся данные поддерживают версию резервного копирования, но недостаточны для окончательного закрытия.

Запись в репозиторий резервных копий, действительная подпись и совпадение с регламентным заданием указывают на легитимную активность. Неподтверждёнными остаются происхождение конкретного экземпляра `backupagent.exe` и его связь с `BK-DAILY-03`, поэтому оповещение не закрыто как ложное срабатывание.

## Рекомендации

- Проверить происхождение `backupagent.exe`: дерево процессов, путь и хеш исполняемого файла.
- Подтвердить связь процесса с заданием `BK-DAILY-03` и статус завершения задания у IT-Operations.
- После проверки принять решение о закрытии оповещения или эскалации.

## Эталонный результат

- **Классификация:** False Positive — легитимное резервное копирование.
- **Критичность:** Low.
- **Уверенность:** High.

Направление выводов совпадает: шифровальщик не подтверждён, T1486 не назначена. Главное расхождение в решении: эталон допускает закрытие как легитимной активности, а при первоначальном разборе закрытие было отложено до дополнительного подтверждения.
