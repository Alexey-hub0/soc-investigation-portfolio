## Исходное оповещение

Первое событие записи [INC-030](evidence/original-events.jsonl):

```text
2026-07-02T17:10:00Z identity_provider src_ip=203.0.113.240 targeted_users=33 failures=45 window_minutes=27 error=invalid_password
```

Identity Provider зафиксировал 45 неудачных попыток аутентификации с ошибкой `invalid_password` на 33 учётных записях за 27 минут, все с одного IP `203.0.113.240`. Это сводная запись: отдельных событий по каждой попытке в датасете нет.

## Результаты анализа

**Неудачные попытки входа.** На 33 учётные записи приходится 45 ошибок, в среднем меньше двух на каждую. Большое количество затронутых учётных записей при небольшом среднем числе ошибок соответствует признакам Password Spraying.

**Успешная аутентификация.** С того же IP зарегистрирован успешный вход подрядчика. MFA выполнена успешно, но устройство не подтверждено как доверенное (`device_id=unknown`). Списка 33 затронутых учётных записей нет, поэтому неизвестно, были ли неудачные попытки под учётной записью подрядчика.

**Проверка контекста.** HR подтверждает активный статус нового подрядчика, работа которого началась в день инцидента. Однако IP отсутствует в разрешённых сетях, поэтому легитимность источника не установлена.

**Результат.** Выявлены признаки Password Spraying и успешная аутентификация с неподтверждённого источника. Компрометация не доказана, но оповещение требует дальнейшего расследования.

## Сопоставление с MITRE ATT&CK

[T1110.003 — Password Spraying](https://attack.mitre.org/techniques/T1110/003/) относится к тактике Credential Access и описывает проверку одного или нескольких паролей на множестве учётных записей. Сопоставление основано на распределении ошибок и не показывает, какие пароли использовались. Успешный вход с MFA не даёт оснований назначать техники обхода MFA.

## Вердикт

**Вердикт:** подозрительная активность с признаками Password Spraying.

**Критичность:** High.

**Уверенность:** умеренная для версии Password Spraying.

**Решение:** рекомендована эскалация и проверка успешной сессии.

Высокая критичность обусловлена успешной аутентификацией с того же неразрешённого IP на фоне массовых ошибок. Версия легитимного входа нового подрядчика учтена, но не позволяет закрыть оповещение: источник подключения и устройство не подтверждены, а действия после входа неизвестны. Имеющиеся события не позволяют подтвердить компрометацию учётной записи.

## Рекомендации

- Проверить личность и обстоятельства входа подрядчика через спонсора учётной записи по доверенному каналу.
- Проверить устройство и действия после аутентификации по журналам облачных сервисов.
- Проанализировать остальные затронутые учётные записи и получить детализацию неудачных попыток.
- При неподтверждённом источнике рассмотреть временное ограничение доступа учётной записи и входов с этого IP.
